STM32H7 CRITICAL HARDWARE NOTES

Advanced configuration required for production-grade firmware

#1 CRITICAL: D-Cache Coherency (MPU Configuration)

The STM32H7 has a Data Cache that WILL corrupt your Ethernet and FDCAN data if not properly configured. The CPU reads from cache while DMA writes to RAM, causing stale data reads.

// MANDATORY: Configure MPU for non-cacheable regions
// Place in main.c BEFORE HAL_Init()

void MPU_Config(void) {
  MPU_Region_InitTypeDef MPU_InitStruct = {0};
  HAL_MPU_Disable();

  // Ethernet DMA Descriptors & Buffers (SRAM3)
  MPU_InitStruct.Enable = MPU_REGION_ENABLE;
  MPU_InitStruct.Number = MPU_REGION_NUMBER0;
  MPU_InitStruct.BaseAddress = 0x30040000; // SRAM3 start
  MPU_InitStruct.Size = MPU_REGION_SIZE_32KB;
  MPU_InitStruct.SubRegionDisable = 0x0;
  MPU_InitStruct.TypeExtField = MPU_TEX_LEVEL0;
  MPU_InitStruct.AccessPermission = MPU_REGION_FULL_ACCESS;
  MPU_InitStruct.DisableExec = MPU_INSTRUCTION_ACCESS_ENABLE;
  MPU_InitStruct.IsShareable = MPU_ACCESS_NOT_SHAREABLE;
  MPU_InitStruct.IsCacheable = MPU_ACCESS_NOT_CACHEABLE;
  MPU_InitStruct.IsBufferable = MPU_ACCESS_NOT_BUFFERABLE;
  HAL_MPU_ConfigRegion(&MPU_InitStruct);

  // FDCAN Message RAM (0x4000AC00 for FDCAN1)
  MPU_InitStruct.Number = MPU_REGION_NUMBER1;
  MPU_InitStruct.BaseAddress = 0x4000A000;
  MPU_InitStruct.Size = MPU_REGION_SIZE_4KB;
  MPU_InitStruct.IsCacheable = MPU_ACCESS_NOT_CACHEABLE;
  HAL_MPU_ConfigRegion(&MPU_InitStruct);

  HAL_MPU_Enable(MPU_PRIVILEGED_DEFAULT);
}

// In main():
MPU_Config();
SCB_EnableICache();
SCB_EnableDCache();
HAL_Init();

Without MPU: Random packet loss, corrupted CAN frames, system hangs after minutes/hours of operation.

#2: GPIO Speed Configuration (OSPEEDR)

SPI signals above 25MHz require GPIO_SPEED_FREQ_VERY_HIGH to maintain signal integrity. The H7 default is MEDIUM, which causes setup/hold violations at high frequencies.

// SPI1 for RFID (can run up to 60MHz)
GPIO_InitStruct.Pin = GPIO_PIN_5|GPIO_PIN_6; // PA5(SCK), PA6(MISO)
GPIO_InitStruct.Pin |= GPIO_PIN_5; // PB5(MOSI)
GPIO_InitStruct.Mode = GPIO_MODE_AF_PP;
GPIO_InitStruct.Pull = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_VERY_HIGH; // Critical!
GPIO_InitStruct.Alternate = GPIO_AF5_SPI1;
HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);

// SPI2 for LCD (display refresh rate depends on this)
GPIO_InitStruct.Pin = GPIO_PIN_2|GPIO_PIN_3; // PC2(MISO), PC3(MOSI)
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_VERY_HIGH;
GPIO_InitStruct.Alternate = GPIO_AF5_SPI2;
HAL_GPIO_Init(GPIOC, &GPIO_InitStruct);

GPIO_InitStruct.Pin = GPIO_PIN_3; // PD3(SCK)
HAL_GPIO_Init(GPIOD, &GPIO_InitStruct);

Symptom: LCD artifacts, RFID read errors, intermittent SPI failures at high clock rates.

#3: FDCAN Clock Configuration

The FDCAN peripheral MUST use HSE or PLL-derived clock, NOT HSI. The HSI has temperature drift (plus/minus 1%) that violates CAN bit timing tolerances.

// In SystemClock_Config() or CubeMX Clock Tree:

// Option 1: Use PLL1Q for FDCAN (recommended)
RCC_PeriphCLKInitTypeDef PeriphClkInitStruct = {0};
PeriphClkInitStruct.PeriphClockSelection = RCC_PERIPHCLK_FDCAN;
PeriphClkInitStruct.FdcanClockSelection = RCC_FDCANCLKSOURCE_PLL;
HAL_RCCEx_PeriphCLKConfig(&PeriphClkInitStruct);

// PLL1Q should output 20-80MHz for optimal FDCAN operation
// Example: 480MHz / DIVQ=10 = 48MHz FDCAN clock

With HSI: CAN bus errors increase with temperature changes, intermittent communication failures.

#4: 480MHz Operation (VOS & Over-drive)

To run at 480MHz, you MUST configure Voltage Scaling and enable Over-drive mode. Default HAL configuration runs at 400MHz.

// In main() before SystemClock_Config():

// Enable CPU ICache and DCache
SCB_EnableICache();
SCB_EnableDCache();

// Configure Voltage Scaling to VOS0 (480MHz capable)
__HAL_PWR_VOLTAGESCALING_CONFIG(PWR_REGULATOR_VOLTAGE_SCALE0);
while(!__HAL_PWR_GET_FLAG(PWR_FLAG_VOSRDY)) {}

// In SystemClock_Config():
RCC_ClkInitStruct.SYSCLKDivider = RCC_SYSCLK_DIV1; // 480MHz
// Latency for 480MHz @ VOS0 with VDD=3.3V:
RCC_ClkInitStruct.FlashLatency = FLASH_LATENCY_4;

Power consumption: ~350mA at 480MHz. Consider thermal management in enclosed designs.

Additional Critical Notes

  • SDMMC vs FMC: PC8-PC12 shared between SDMMC1 and FMC. Cannot use SD Card and external SDRAM simultaneously.
  • ADC on PA0: USER_BUTTON pull-down (R33) will distort readings. Not suitable for precision analog.
  • USB OTG: PA11/PA12 have series resistors (R52/R53) for protection. May affect signal integrity at High-Speed USB.
  • Ethernet PHY: LAN8742A requires 50MHz ref clock from PA1. If disabled, Ethernet is non-functional.
  • I2C Pull-ups: Nucleo does NOT have I2C pull-ups on PF0/PF1. External 4.7k required.
  • CAN Transceiver: NOT included on Nucleo. External TJA1050/MCP2551 + 120 ohm termination required.
